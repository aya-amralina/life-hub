## 1. Сроки у пунктов: четыре вида (все сферы)

У пункта (`items`) может быть ноль, одна или несколько дат. Вид определяется по заполненным полям:

| Вид | Поля | Поведение |
| --- | --- | --- |
| **Открытый** | дат нет | висит до смены статуса |
| **В определённый день** | `happens_on`, `happens_time` (необяз.) | в этот день появляется в «Сегодня» и в календаре; если день прошёл, а пункт не закрыт — вопрос «Состоялось?»: да → готово, «другая дата», «отменить» |
| **Начинается с даты** | `starts_on` | до этой даты скрыт из активных списков, виден в свёрнутой группе «Скоро» и в календаре; с этой даты — обычный пункт |
| **С дедлайном** | `due_date`, `due_time` (необяз.) | «Горит» за 3 дня, после срока — «просрочено» |

`starts_on` и `due_date` можно сочетать («начать с 01.12, сдать до 15.12»). Статусы Работы остаются как в таблице.

**Новые поля `items`:** `starts_on date`, `happens_on date`, `happens_time time`, `is_fixed bool` (Учёба), `rollover_count int default 0`.

## 2. Перенос невыполненного

### Учёба
- **Жёсткий пункт** — есть официальный срок (`due_date`): HA, тесты, Hausarbeit, сдачи. **Гибкий** — без официального срока: лекции, сверки, подготовка. По умолчанию `is_fixed = due_date is not null`, на карточке можно переключить.
- **Гибкие переносятся сами.** При первом открытии приложения в новой неделе все незакрытые гибкие пункты прошлых недель переезжают в текущую, `rollover_count += 1`. Без серверного cron — проверка на клиенте, идемпотентная.
- **Проверка ёмкости.** Если после переноса неделя превышает максимум, лишние пункты не переносятся молча, а попадают в список «Ждут решения» (баннер на Учёбе и шаг в воскресном обзоре): выбрать неделю или снять.
- **«Застряло».** При `rollover_count ≥ 2` пункт помечается «застряло». В обзоре три действия: разбить на части, снять, поставить на конкретную неделю.
- **Жёсткие не двигаются.** После «готово к» — горят, после срока — «просрочено» с действиями «сдано позже» (готово) и «снять».

### Работа
- Автопереноса нет. Пункт висит до смены статуса.
- «Status alt» через 14 дней без изменений — как было.
- Виды сроков — по разделу 1.

### Тело
- Привычки не переносятся: пропущенный день просто прошёл.
- Разовые задачи и визиты — обычные пункты по разделу 1.

### Деньги
- Перерасход режется следующей неделей (как было, с подтверждением).
- Плановая операция, не подтверждённая в свой день: вопрос «Пришло?» на «Сегодня» и в Деньгах → «подтвердить» (сумму можно поправить), «другая дата», «отменить».

## 3. Тело: новое

### 3.1 Активности со скором
Одна тренировка в день — мало, поэтому активности хранятся отдельно, по нескольку в день.

```
activity_types   name, intensity ('лёгкая'|'средняя'|'интенсивная'), points_per_10min, active, sort_order
activities       date, type_id, minutes, note
```

- **Скор активности** = `minutes / 10 × points_per_10min`. По умолчанию: лёгкая — 1, средняя — 2, интенсивная — 3 очка за 10 минут. Типы и очки редактируются в Настройках → Активности.
- Стартовый список типов взять из листов «Программа» и «Трекер» глоу-апа; интенсивность по умолчанию — средняя, Ая поправит сама.
- **Миграция:** поля `workout_type` и `workout_min` из `daily_logs` переносятся в `activities`, на «Отметке дня» блок «Движение» позволяет добавить несколько активностей. Старые колонки удалить отдельной миграцией после переноса.
- **Цель недели по скору** — поле в `plan_stages.targets` (по этапам), редактируется.

### 3.2 Приём витаминов и лекарств
Не ежедневная отметка, а периоды: что, с какого числа, когда закончила.

```
intake           name, kind ('витамин'|'лекарство'|'другое'), dose text, schedule text,
                 start_date, end_date (null = принимаю сейчас), note
```

- Экран Тело → **Приём**: «Сейчас принимаю» и свёрнутый архив. Кнопка «Закончила» ставит `end_date = сегодня`.
- Только внутри приложения: не попадает в «Горит» и в календарь по умолчанию (в календаре — фильтр, выключен).

## 4. Визуализации (новый этап, после импорта)

На «Сегодня» графиков нет.

| Секция | Что показать |
| --- | --- |
| **Деньги** | линия баланса до 31.12: план против факта; заполнение конвертов (заложено / потрачено / осталось) |
| **Работа** | доска по статусам; Erfolge по месяцам столбиками |
| **Учёба** | тепловая карта загрузки Н00–Н25 против ёмкости (ок / нужен Do/Sa ½ / перегруз); прогресс по предметам в часах |
| **Тело** | календарь привычек (как на GitHub); график настроения, энергии и сна с переключателем **День / Неделя / Месяц** (день — значения по дням, неделя и месяц — средние); скор активностей по неделям против цели + таблица активностей; рост повторов по упражнению |

Детали графика самочувствия:
- Настроение и энергия — линии по шкале 1–10, сон — столбики в часах на второй оси.
- Опциональный переключатель «Показать приём»: периоды из `intake` полосами на фоне графика. Без выводов и подсказок о причинах — только наложение.
- Пустые дни — разрывы линии, а не нули.

Все графики — Recharts, цвета сфер из дизайн-системы, светлая и тёмная тема, подписи осей на русском.

## 5. Календарь внутри приложения

Только внутри приложения, без экспорта .ics и без синхронизации с внешними календарями.

- **Вход:** иконка календаря в шапке «Сегодня» рядом с настройками; в каждой сфере — вид «Календарь», отфильтрованный по этой сфере. Шестой вкладки нет.
- **Виды:** Месяц (точки цвета сферы под датой, тап по дню — список) и Неделя (дни столбиком, события со временем).
- **Что показывается:**
  - пункты с `due_date`, `happens_on`, `starts_on` (отметка «начало»);
  - тесты и дедлайны Учёбы;
  - плановые операции Денег;
  - дни замеров;
  - недели с местом и режимом (поездки, Казахстан) — полосой поверх дней;
  - границы этапов глоу-апа;
  - периоды приёма — только если включён фильтр.
- **Фильтры** чипами по сферам, состояние фильтров запоминается (localStorage).
- Тап по событию открывает карточку пункта; из календаря можно создать пункт на выбранный день через «+».

## 6. Импорт: что меняется

- **Dry-run не запускать, пока Ая не напишет, что данные в `data/` отредактированы.** Перед dry-run заново проверить структуру листов и сообщить, если колонки изменились.
- «Трекер» глоу-апа: тренировка → `activities` (тип сопоставить со справочником, неизвестные типы — показать в dry-run).
- Чеклист учёбы: `is_fixed` по правилу раздела 2.
- Если в таблицах встретятся даты «с …» или события в конкретный день — заполнить `starts_on` / `happens_on`; спорные случаи показать в dry-run.

## 7. Этапы (новая нумерация)

3. **Импорт и логика** — как в SPEC плюс: виды сроков (раздел 1), правила переноса (раздел 2), «Пришло?», активности со скором и приём (раздел 3, экраны-списки без графиков).
4. **Визуализации и календарь** — разделы 4 и 5. *Готово:* у каждой сферы, кроме «Сегодня», есть свой график; календарь показывает события всех сфер с фильтрами.
5. **Обзор и экспорт** — бывший этап 4: воскресный обзор (с шагами «Ждут решения» и «Застряло»), экспорт и восстановление, хотелки 48 ч, офлайн-очередь.
6. **Потом** — бывший этап 5.

### Unit-тесты на новые правила
- вид срока по набору полей;
- автоперенос гибких: идемпотентность, `rollover_count`, неделя с переполнением → «Ждут решения»;
- «застряло» при `rollover_count ≥ 2`;
- жёсткий пункт не переносится;
- «Состоялось?» после `happens_on`;
- `starts_on` скрывает пункт до даты;
- скор активности и сумма недели;
- приём: активен, если `start_date ≤ сегодня` и (`end_date` пусто или `≥ сегодня`).
