# Life Hub — план работ

Этапы — из раздела 7 SPEC. После каждого этапа: `lint` + `test` + `build` зелёные → коммит в `main` → автодеплой → короткий отчёт «что проверить на телефоне».
Обозначения: 👤 — нужно твоё действие (дам инструкцию в 3–5 шагов и подожду), ❓ — вопрос, который задам в нужный момент.

## Этап 1. Каркас
**Готово, когда:** прод-ссылка `*.vercel.app` открывается, приложение ставится на телефон, вход по e-mail и паролю работает (magic link — запасной в браузере), данные синхронизируются между телефоном и ноутбуком.

1. Окружение: Node 24 через nvm (сейчас стоит Node 20, а свежим React Router, supabase-js и Vitest нужен ≥ 22), `.nvmrc`, `engines` в package.json.
2. Проект: Vite + React + TS strict, Tailwind v4, React Router, TanStack Query, ESLint, Vitest, Playwright; `git init`, `.gitignore` (уже создан).
3. Дизайн-система → код: токены светлой и тёмной темы (CSS-переменные + `@theme`), шрифт Onest (self-hosted), тема «как в системе / светлая / тёмная».
4. Базовые компоненты: Button, Card, SegmentedTabs, TabBar, Fab «+», BottomSheet (пока пустой), Toast, Skeleton, EmptyState, OfflinePill.
5. Supabase: `supabase init`, миграция 0001 — общие функции (триггер `updated_at`), таблицы `weeks` и `items`, индексы, `unique (user_id, source_id)`, RLS + 4 политики.
6. Авторизация: экран «Вход» (e-mail + пароль → `signInWithPassword`, autocomplete для менеджера паролей; запасная кнопка magic link, `shouldCreateUser: false`), обработка возврата по ссылке, защита роутов, выход.
7. Оболочка: таб-бар «Сегодня · Деньги · Работа · Учёба · Тело», роуты сфер с заглушками, «+» на всех экранах, пустой «Сегодня» (дата, пустые состояния), «Настройки» (тема, выход).
8. Проверка синхронизации: на «Сегодня» временный блок «Заметка дня» — один пункт в `items` (sphere personal), видно с обоих устройств. Уберу на этапе 2.
9. PWA: manifest (имя, цвета из токенов, `display: standalone`), иконки 192/512/maskable + apple-touch-icon, service worker (precache оболочки), подсказка «Добавить на экран» для iOS.
10. Деплой: `vercel.json` (SPA rewrite), README (черновик: локальный запуск и деплой).
11. Тесты: Vitest — `lib/dates`, `lib/format`; Playwright — дымовой: вход + «Сегодня».
12. 👤 **Твои действия** (дам точные шаги):
    - создать приватный репозиторий `life-hub` на GitHub и настроить доступ для `git push` из WSL (SSH-ключ или токен);
    - создать проект Supabase Free (Frankfurt), вписать `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` (`sb_publishable_…`), `SUPABASE_SECRET_KEY` (`sb_secret_…`) в `.env.local`, выполнить `npx supabase login`;
    - в Supabase Auth: Site URL, Redirect URLs, создать своего пользователя, выключить регистрацию;
    - импортировать репозиторий в Vercel и задать env-переменные.

## Этап 2. Ежедневные отметки
**Готово, когда:** день отмечается без Excel.

1. Миграция 0002: `daily_logs`, `plan_stages`, `transactions`, `week_limits`, `envelopes`, `notes` (+ RLS).
2. Правила (Vitest): №2 «неделя денег», №12 «этап глоу-апа», №13 «режим минимум», №14 «процент привычек», №7 «загрузка недели» (базовая версия).
3. Компоненты: HabitButton, Scale 1–10, Chip / чип категории с остатком, ProgressBar (в т.ч. перерасход), CheckItem (обычный / выполнен / срок прошёл / недоступен), StatusBadge.
4. Тело → «Отметка дня»: привычки этапа, тренировка + минуты, уход, энергия / сон / настроение / провал, «минимум», заметка. Автосохранение.
5. Деньги → «Неделя»: лимиты 6 категорий, факт, отклонение, статус. Быстрая трата через «+» (сумма → категория → счёт, ≤ 3 тапов), тост «Отменить».
6. Учёба → «Неделя»: ёмкость, пункты по предметам, чекбоксы.
7. Работа → список, сгруппированный по статусам, смена статуса (лист), создание пункта.
8. «+» → bottom sheet: Трата / Пункт / Заметка.
9. «Сегодня»: строка недели, привычки дня, «Горит» (базово), полоса лимита + «+ трата», Работа (In Arbeit + nachhaken), Учёба (часы недели + ближайший тест), вечерний блок.
10. Ручной ввод недель и лимитов: до импорта будет минимальный экран, после импорта данные придут из Excel.

## Этап 3. Импорт и логика
**Готово, когда:** проверки раздела 6 SPEC зелёные.

1. Миграция 0003: `people`, `strength_sets`, `measurements`, `wishlist`, `reviews` (+ RLS) и недостающие поля.
2. Скрипт `scripts/import/import.py`: общий слой (поиск файлов, Excel-даты-числа, тексты «Fr 23.10», «Mi 28.10 10:00», «Fr 30.10 (допущ.)», год окт–дек → 2026, янв–апр → 2027), upsert по `(user_id, source_id)`, `--dry-run` со сводкой, лог без содержимого строк.
3. Импорт Budget: Статьи → transactions (S0 → opening, знак → income/expense, дата ≤ дня импорта → подтверждено), Календарь → account + note операций, Недели → weeks (неделя 1 = 12.10–18.10) + week_limits, Конверты и копилки → envelopes, Правила → notes (pinned).
4. Импорт Localiser: Dev Aufgaben → items (work) — единственный источник; строка с пустым Titel (Branch `fix/h2_secret_logging`) → «PR 1: Secret-Logging fixen»; Legende → people + notes. Organisatirisch не читается.
5. Импорт WiSe: Чеклист → items (study, без 2 строк-инструкций), «↔ / ⚠» → synergy/trap, Дедлайны и тесты → data_status или новые пункты Тест/Орга, План по неделям → weeks (режим, ёмкость), Допущения → notes.
6. Импорт Глоу-ап: Трекер → daily_logs (только заполненные), Сила → strength_sets, Замеры → measurements (+ напоминания body), Задачи и Врачи → items (визиты — тип «Визит»), Обзор и Недели → plan_stages + события в weeks, Программа / Питание / Уход / гибкость → notes.
7. Unit-тесты парсеров (`python -m unittest`).
8. Правила (Vitest): №1 баланс и прогноз, №3 перерасход → лимит следующей недели, №4 конверты, №6 «готово к», №7 полностью (½-режим), №8 перенос, №9 Status alt, №10 Nachhaken, №11 «Горит» (все сферы).
9. Экраны: Работа — доска (сгруппированный список), по Bereich, Bei wem nachhaken, Erfolge, Люди, пятничный обзор; Учёба — дедлайны и тесты (обратный отсчёт, значок data_status), предмет (часы, ↔ / ⚠), перенос на следующую неделю; Тело — силовые (журнал + график повторов), замеры, задачи и визиты, справка; Деньги — операции (план/факт, подтверждение одним тапом, фильтры), конверты, месяцы (как лист «Обзор»), правила, прогноз «На счетах 31.12».
10. Жесты: свайп вправо — готово, влево — перенести, долгий тап — карточка.
11. `npm run test:import`: остаток на 31.12.2026 = 1788,14 €; задач Работы = непустых строк Dev Aufgaben; часов Н04 = 27,5; пунктов чеклиста = строк Чеклиста.
12. 👤 Запуск импорта на твоей базе: сначала `--dry-run`, ты смотришь сводку, затем запись.

Решено: «Календарь» → «Счёт» в `account` сопоставленной операции, «Что сделать» → её `note`; в `--dry-run` — список строк, похожих на открытые действия, ты выбираешь, какие станут задачами Денег.

## Этап 4. Обзор, графики, экспорт
**Готово, когда:** воскресенье проходит целиком в приложении.

1. Воскресный обзор: мастер из 5 шагов (Деньги → Тело → Учёба → Работа → Неделя вперёд), пропуск шага, сохранение в `reviews`; предложение срезать лимит следующей недели (правило №3, только после подтверждения).
2. Тело → «Итоги недели»: графики Recharts (привычки %, энергия / сон / настроение, силовые, замеры).
3. Хотелки: список, правило 48 часов (№5), решение «купить / не покупать».
4. Настройки: экспорт JSON (все таблицы) и CSV (по таблице), импорт JSON (восстановление, upsert по `id`, с подтверждением и предварительной сводкой).
5. Офлайн-очередь: мутации в IndexedDB, отправка при появлении сети, плашка «Офлайн · N изменений ждут сети», runtime-кэш данных для чтения.
6. Состояния на всех экранах: пусто, всё выполнено, просрочено, перерасход, офлайн, скелетоны.
7. Опционально: GitHub Action keep-alive (лёгкий запрос раз в сутки); 👤 секреты в GitHub.
8. README полностью: локальный запуск, деплой, экспорт, восстановление из экспорта.
9. Финальная проверка: доступность (контраст AA, тап-зоны), Lighthouse PWA, e2e.
