# Life Hub · Деньги: новая логика и редизайн

Рабочий документ для Claude Code. Делаем по фазам, одна фаза = одна сессия.
Если по ходу что-то решили иначе — сначала правим этот файл.

## Проблема

Конверт резервирует свою сумму сразу при создании, неважно, на когда он запланирован.
Подарки (165 €, декабрь), Рождество с друзьями (70 €, декабрь) и Казахстан (30 €, конец декабря)
сейчас «съедают» ноябрьские деньги, хотя платить за них будут декабрьские:

- Revolut · Основной: 31,99 € на счёте, «свободно −253,01 €»
- Баланс: 105,92 €, «свободно −179,08 €»
- «Свободно до 27.11»: −201 € (судя по цифрам, это −179,08 € минус остаток недельного лимита до 27.11, ≈ 21,92 €)

## Цели

1. Деньги текущего периода не уходят на планы будущих периодов, если я сама не решила отложить заранее.
2. Конверты становятся просто запланированными тратами с датой.
3. Меньше разделов и визуального шума: всё про будущее — в одном месте, по периодам.
4. Текущий стиль (цвета, шрифт) сохраняем. Меняется структура, не айдентика.

## Новая логика

### Период

Период — деньги от одного дня денег до следующего. Называется по месяцу, который покрывает («Декабрь»).
Какая выплата задаёт границы — решаем в фазе 0 (см. «Открытые вопросы»).

### Запланированная трата — одна сущность вместо пяти

Конверты, хотелки, возвраты долгов и переводы в копилки — это всё «деньги, которые уйдут потом».
Делаем одну сущность с типом:

```ts
PlannedItem {
  id, title, amount
  when: { date?: string; month?: string } | null  // null = «Когда-нибудь» (бывшие хотелки)
  periodId          // из каких денег платим; по умолчанию — период, в который попадает дата
  kind: 'spend' | 'debt' | 'to_goal'
  accountId         // по умолчанию Revolut · Основной
  reservedEarly     // true = «отложить сейчас», из денег текущего периода
  goalId?           // для to_goal
  recurringId?      // если создана из регулярного платежа
}
Transaction { ...; plannedItemId? }  // траты привязываются к плану
```

Регулярные платежи — шаблоны, которые создают PlannedItem в каждом периоде.
Это набросок, адаптировать под текущую схему и базу.

### Статусы (вычисляются)

- **Запланировано** — период ещё не начался. В «свободно» не участвует, видно в прогнозе своего периода.
- **Отложено** — период начался или нажато «Отложить сейчас». Вычитается из свободного.
- **Идёт** — есть траты, вычитается только остаток.
- **Готово** — закрыто. Остаток вернулся в свободное; перерасход виден как «+X € сверх» в истории.

### Формула «Свободно до дня денег»

```
свободно = сумма счетов в балансе
         − остатки трат со статусом «Отложено» / «Идёт»
         − регулярные платежи до дня денег
         − долги со сроком до дня денег
         − остаток недельного лимита до дня денег   (как сейчас)
```

Траты будущих периодов не вычитаются. «Свободно» по счёту — то же самое, только по одному счёту.

**Проверка на реальных данных:** Подарки, Рождество, Казахстан уходят в декабрь →
«Свободно до 27.11» ≈ 105,92 − 20 − 21,92 ≈ **+64 €** (было −201 €),
Revolut · Основной ≈ **11,99 €** (было −253,01 €).

### Прогноз периода

Для каждого будущего периода:

```
ожидаемые поступления
− регулярные
− запланированные траты
− в копилки
− возврат долгов
= на жизнь   (и сколько это в неделю, сравнить с недельным лимитом)
```

Если не сходится — «Декабрь не сходится на X €» и действие «Перенести в другой период».
Минус не прячется в текущем месяце, а честно виден там, где он есть.

### Долги и копилки

- **Я должна** (Жилец, депозит 100 € до 30.11) → трата типа `debt` в нужном периоде.
- **Заём из копилки** (Подушка: Revolut, 130 €) → копилка помнит, сколько из неё взято;
  возвраты — траты типа `to_goal` по периодам. Длинный текст про заём в карточке цели убираем.
- **Копилки** (Подушка: Revolut, Подушка: казахстанская карта, Январь) остаются отдельно — это не траты.
  Взнос в копилку в каждом периоде виден в прогнозе периода.

## Новая структура раздела «Деньги»

Три вкладки вместо семи разделов:

```
Деньги
├─ Сейчас   — главный экран: что можно тратить до дня денег
├─ План     — всё про будущее, по периодам
└─ Счета    — счета, копилки, долги
   Заметки → в меню «Ещё»
```

Что куда переезжает:

| Было | Стало |
|---|---|
| Неделя, категории, траты недели | Сейчас |
| Счета «Баланс» | Сейчас (одно число) + Счета (подробно) |
| Конверты | План |
| Месяц план и баланс | План, итог периода (в фазе 0 проверить, что там сейчас) |
| Регулярные | План (свёрнутой строкой в каждом периоде) + шаблоны в Счетах |
| Хотелки | План → «Когда-нибудь» |
| Долги | План (возвраты) + одна строка в Счетах |
| Цели | Счета → Копилки |

### Сейчас

```
Свободно до 27.11
64 €                                   как посчитано ▾
──────────────────────────────────────────────
Неделя 16.11–22.11                    17 из 25 €
▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░                осталось 8 €
Продукты 9,06   Выходы 2,90   Мелочи 5 из 10
──────────────────────────────────────────────
До дня денег
Дорога в Берлин                        20 €
──────────────────────────────────────────────
Траты недели                                все
NORMA            Продукты        вт     9,06 €
Zoo Palast       Выходы          вт     2,90 €
Apotheke         Мелочи          пн     5,00 €
```

«Как посчитано» раскрывает формулу на текущих числах.

### План

```
Ноябрь · до 27.11                       сходится
  Дорога в Берлин                          20 €

Декабрь · с 27.11                  на жизнь … €
  Поступления                             … €
  Регулярные (3)                          … €  ▸
  Подарки                                165 €
  Рождество с друзьями                    70 €
  Казахстан                  конец дек.   30 €
  Жилец, депозит             до 30.11    100 €
  В копилки                               … €
  ───────────────────────────────────────────
  На жизнь                   ≈ … € в неделю

Январь
  …

Когда-нибудь
  (бывшие хотелки)

Готово (5) ▸   Кипр, Франкфурт, Рисование с подругой…
```

### Счета

Баланс одним числом, под ним счета: на счёте / отложено / свободно.
Копилки: прогресс, темп, когда при таком темпе дойду.
Долги: одна строка на долг, подробности по тапу.

## Правила визуала

- Одна карточка на раздел, внутри строки. Не карточка на каждый конверт.
- Прогресс-бар только когда уже что-то потрачено. Пока 0 € — сумма и дата.
- Метастрока — только то, что влияет на решение: «165 € · декабрь» вместо «заложено 165 € · потрачено 0 € · декабрь».
- Закрытое уходит в «Готово (N)», свёрнуто.
- Цвета: зелёный — всё ок, охра — сверх плана, красный — только «не сходится» / минус.
- Одно главное число на экран.
- Категория без лимита не пишет «сверх лимита», просто показывает сумму (сейчас «Продукты 9,06 / 0 € · +9,06 € сверх лимита»).
- Длинные пояснения — в «подробнее» или в саму структуру данных.
- Суммы выровнены вправо, `font-variant-numeric: tabular-nums`.

## Фазы

### Фаза 0 — Разбор (без изменений кода)

- Разобрать модуль «Деньги»: где хранятся конверты, долги, цели, регулярные, хотелки, «Месяц план и баланс».
- Как сейчас считаются «свободно», «свободно» по счёту и «Свободно до 27.11», откуда дата 27.11.
- Предложить переход к модели из этого файла с минимальной миграцией.
- Бэкап / экспорт текущих данных.

**Готово, когда:** понятно, как устроено сейчас, есть бэкап, закрыты открытые вопросы.

### Фаза 1 — Быстрый фикс логики

- Конвертам — период оплаты и вычисляемый статус. Миграция существующих по их датам
  («декабрь», «конец декабря» → Декабрь; «конец ноября» → текущий).
- «Свободно» и «свободно» по счёту не учитывают траты будущих периодов.
- Кнопка «Отложить сейчас».

**Готово, когда:** на реальных данных «Свободно до 27.11» ≈ +64 €, Revolut · Основной ≈ 11,99 €,
декабрьские конверты видны с пометкой периода. Деплой.

### Фаза 2 — Единая модель

- Свести конверты, хотелки, возвраты долгов и переводы в копилки к PlannedItem.
- Регулярные — шаблоны, создающие PlannedItem по периодам.
- Миграция; старые экраны временно читают новую модель.

**Готово, когда:** все данные на месте, ничего не задвоилось, все суммы совпадают с фазой 1.

### Фаза 3 — Экран «План»

- Периоды: текущий + 2 следующих, «Когда-нибудь», «Готово».
- Итог периода и предупреждение «не сходится».
- Одна форма создания и редактирования, перенос в другой период.

### Фаза 4 — Экран «Сейчас»

- Главное число + «как посчитано».
- Неделя одним блоком, категории компактно.
- «До дня денег» и последние траты.

### Фаза 5 — «Счета» и уборка

- Счета, копилки, долги на одном экране.
- Удалить старые страницы, Заметки → «Ещё».
- Пройтись по всем экранам по правилам визуала.

### Фаза 6 — День денег (потом)

Когда приходят деньги — экран распределения: пришло X → регулярные, планы периода, копилки, долги →
сколько остаётся на жизнь и какой выходит недельный лимит. Подтвердить одной кнопкой.

## Как работать с Claude Code

- Файл лежит в репо: `docs/money-redesign.md`.
- Начало сессии: «Прочитай docs/money-redesign.md, делаем фазу N. Сначала план, потом код.»
- После фазы: проверить на своих числах → коммит → деплой.
- **Фаза 3 (20.11.2026).** Экран «План» — `/money/plan` в «Ещё» (вкладки «Сейчас / План / Счета» — фаза 5).
  `rules/planPeriods.ts`: периоды, «на жизнь», «не сходится»; считается только «Баланс» (депозит Жильца на «Депозите»
  в декабрьский итог не входит, а его возврат с Основного — входит). Одна форма для трат и хотелок; долги и операции —
  свои листы (период = дата). На данных 19.11: Декабрь — поступления 1 574 €, регулярные 219 €, траты 805 €, в копилку 30 €,
  долг 100 € → на жизнь ≈ 420 € (≈ 95 € в неделю при лимите 72 €); Январь — ≈ 520 €.
- **Фаза 4 (20.11.2026).** «Сейчас» — главный вид `/money` (заголовок пока «Деньги», вкладки — фаза 5): главное число
  `FreeUntilHero` + «как посчитано», неделя одним блоком с компактными категориями, «До дня денег» из плана, последние
  5 трат и «Все · N». Ничего из прежнего вида не убрано: переключатель недель, лимиты, темп, урезание следующей недели,
  свайп «Удалить».
- **Фаза 5 (20.11.2026).** Вкладки «Сейчас · План · Счета» (`RouteTabs`); «Ещё» — Месяц (операции и прогноз — это
  единственный список всех операций, график сценариев и «Месяцы», поэтому не удалён, а убран на второй уровень),
  Регулярные, Заметки. «Конверты и долги» разобраны: конверты — «План», копилки и долги — «Счета» (`SavingsDebts.tsx`,
  по карточке на раздел, строки); «Хотелки» — «План» → «Когда-нибудь» с «Подумать 48 часов». Старые адреса
  перенаправляются. Данные и схема не менялись.
