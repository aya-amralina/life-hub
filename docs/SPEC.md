# Life Hub — спецификация для разработки

Личное веб-приложение (PWA), которое заменяет четыре Excel-трекера: бюджет, задачи Localiser, учебный план WiSe 26/27 и глоу-ап. Пользователь один. Главный экран «Сегодня» собирает главное из всех сфер, раз в неделю — «Воскресный обзор».

Цели: отметка дня ≤ 10 секунд, любая отметка ≤ 3 тапа, итоги недели за 5–10 минут, 0 € в месяц.

Визуал — дизайн-система и экраны Claude Design в `design/`; рабочая выжимка — `docs/DESIGN.md`. Экраны, которых нет в дизайне, собираются из той же системы в стиле экранов 3a–3o (светлая и тёмная тема, пустые состояния, тот же тон текстов). Логика и данные — из этого документа. При расхождении: внешний вид — по дизайну, поведение — по SPEC.

## 2. Деплой и окружения (бесплатно)

1. **GitHub** — приватный репозиторий `life-hub`, ветка `main` = прод.
2. **Supabase Free** — один проект, регион Frankfurt (eu-central-1).
   - Схема — только миграциями: `supabase/migrations/*.sql`, применяются `npx supabase db push`.
   - Auth: e-mail + пароль (основной способ, `signInWithPassword`); magic link — запасной вариант для браузера. Своего SMTP нет, шаблоны писем стандартные. Site URL = прод-адрес на Vercel. Redirect URLs: прод-адрес, `http://localhost:5173` (нужны для magic link).
   - Мой пользователь и отдельный тестовый пользователь создаются вручную с паролем (Dashboard → Authentication → Users), после этого регистрация новых пользователей выключена. Автотесты входят только под тестовым пользователем (`LIFEHUB_TEST_EMAIL`, `LIFEHUB_TEST_PASSWORD`) и не трогают мои данные; `LIFEHUB_EMAIL` — моя почта для импорта.
   - Бесплатный проект ставится на паузу после 7 дней без активности. При ежедневном использовании это не грозит. Опционально (этап 5): GitHub Action раз в сутки делает лёгкий запрос к базе.
3. **Vercel Hobby** — импорт репозитория, пресет Vite.
   - Env: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` (Production и Preview).
   - `vercel.json` с rewrite всех путей на `/index.html` (SPA).
   - Preview-деплой на каждую ветку.
4. **Локально** — `.env.local` с теми же переменными плюс `SUPABASE_SECRET_KEY` только для скрипта импорта и локальных тестов.

**Ключи API — только нового формата** (legacy `anon` / `service_role` JWT Supabase выводит из употребления к концу 2026): `sb_publishable_…` во фронтенде, `sb_secret_…` локально. Это не JWT: они передаются только в заголовке `apikey`, никогда как `Authorization: Bearer`. Publishable работает от роли Postgres `anon`, secret — от `service_role` (обходит RLS).

### Безопасность и приватность

- RLS на каждой таблице: колонка `user_id uuid not null default auth.uid()`, политики `using (user_id = auth.uid()) with check (user_id = auth.uid())` для select/insert/update/delete.
- Права явно в миграциях (в проекте выключено «Automatically expose new tables», включено «Enable automatic RLS»): `grant select, insert, update, delete` для `authenticated` и `service_role` (импорт); у `anon` прав нет.
- Secret key (`sb_secret_…`, роль `service_role`) никогда не попадает во фронтенд, в переменные с префиксом `VITE_`, в git и в логи. Сборка падает, если в `VITE_*` оказался секретный ключ.
- `.gitignore`: `.env*`, `data/`, `*.xlsx`, экспортированные дампы.
- Фото не хранятся (только отметки «фото сделано»).
- Скрипт импорта не печатает содержимое строк — только счётчики и ошибки с номером строки.

### Сроки у пунктов: четыре вида (все сферы)

У пункта может быть ноль, одна или несколько дат. Вид определяется по заполненным полям, отдельного поля «вид» нет.

| Вид | Поля | Поведение |
| --- | --- | --- |
| **Открытый** | дат нет | висит до смены статуса |
| **В определённый день** | `happens_on`, `happens_time` (необяз.) | в этот день появляется в «Сегодня» и в календаре; если день прошёл, а пункт не закрыт — вопрос «Состоялось?»: «да» → готово, «другая дата», «отменить» |
| **Начинается с даты** | `starts_on` | до этой даты скрыт из активных списков, виден в свёрнутой группе «Скоро» и в календаре (отметка «начало»); с этой даты — обычный пункт |
| **С дедлайном** | `due_date`, `due_time` (необяз.) | «Горит» за 3 дня (у Учёбы — от «готово к»), после срока — «просрочено» |

`starts_on` и `due_date` можно сочетать («начать с 01.12, сдать до 15.12»); старт не позже срока (проверка в базе). Статусы Работы остаются как в таблице.

## 4. Бизнес-правила (считаются, не хранятся; каждое покрыто unit-тестом)

1. **Баланс и прогноз.** Остаток после каждой операции = накопленная сумма со знаком (opening и income +, expense −, transfer 0) в порядке даты. Горизонт скользящий: от сегодня до конца месяца через `FORECAST_MONTHS` = 6 месяцев (17.11.2026 → 31.05.2027); «план на 31.05» = остаток на конец горизонта с учётом плановых операций и повторений регулярных (правило 28). Таблица «Месяцы» — от месяца первой операции до конца горизонта, пустые месяцы тоже.
2. **Неделя денег.** Факт = сумма expense с недельной категорией и без `envelope_id` за неделю. Отклонение = факт − лимит. Статус: ≤ 0 «в лимите», > 0 «перерасход».
3. **Перерасход режется следующей неделей.** При перерасходе приложение предлагает уменьшить лимит следующей недели на сумму перерасхода (только после подтверждения).
4. **Конверты** не входят в лимит недели; карточка конверта показывает заложено / потрачено / осталось.
5. **Хотелки 48 часов.** Если `now − added_at ≥ 48 ч` и решения нет — показать вопрос «всё ещё нужно?».
6. **Готово к** (Учёба) = срок − 2 дня; если выпало на Пн или Вс — сдвиг на предыдущую Сб. Пример: срок Ср 28.10 10:00 → готово к Сб 24.10.
7. **Загрузка недели** = Σ `hours_est` пунктов учёбы недели. Пороги — из ёмкости недели в `weeks`: ≤ `capacity_base_h` «ок», ≤ `capacity_max_h` «нужен Do/Sa ½», больше — «перегруз». По умолчанию 27 / 36 ч; неделя с режимом ½ — 13,5 / 18. Те же пороги у тепловой карты Учёбы.
8. **Перенос вручную.** «Перенести на следующую неделю» меняет `week_id` и сразу пересчитывает загрузку обеих недель.
9. **Status alt.** Пункт Работы не в Erledigt/Verworfen и `updated_at` старше 14 дней.
10. **Nachhaken.** Счётчик по людям: статус Wartet auf Antwort или Blockiert и имя человека встречается в `waiting_on`.
11. **Горит.** Незакрытые пункты всех сфер, где `coalesce(ready_by, due_date) ≤ сегодня + 3 дня` («горит», янтарный), плюс просроченные (`due_date < сегодня`, красный с подписью «срок прошёл»). Сортировка по дате. Пункты с `starts_on` в будущем и приём (`intake`) сюда не попадают. Сделанные сегодня — ниже, в свёрнутой группе «Сделано · N» (по умолчанию закрыта; снять отметку можно оттуда).
12. **Этап глоу-апа** определяется по дате (`plan_stages`) и задаёт набор привычек, набор минимума и цели недели. Не начавшиеся привычки скрыты.
13. **Режим «минимум».** При включённом минимуме видны только привычки набора `minimum_habits` этапа, остальные скрыты. День засчитывается полностью (как все активные привычки), если отмечен весь набор; иначе считаются только отмеченные привычки набора. Текст карточки называет привычки набора («Минимум: вода и 10 минут на улице»).
14. **Процент привычек недели** = отмеченные привычки / (активные привычки × прошедшие дни недели), дни минимума — по правилу 13. Стриков с обнулением нет.
15. **Вид срока** пункта — по набору полей (раздел 3): открытый / в определённый день / начинается с даты / с дедлайном; `starts_on` сочетается с дедлайном.
16. **«Скоро».** Пункт с `starts_on > сегодня` скрыт из активных списков и из «Горит», виден в свёрнутой группе «Скоро» своей сферы и в календаре.
17. **«Состоялось?».** Незакрытый пункт с `happens_on < сегодня` → вопрос на «Сегодня» и в своей сфере: «да» (готово), «другая дата» (новый `happens_on`), «отменить».
18. **«Пришло?» / «Списалось?».** Плановая операция (`is_planned`, без `confirmed_at`), у которой дата наступила (`date ≤ сегодня`), → вопрос на «Сегодня» и в Деньгах: для дохода — «Пришло?», для расхода и перевода — «Списалось?». Действия: «подтвердить» (сумму можно поправить), «другая дата», «отменить» (`cancelled_at`: строка остаётся, но выходит из плана и баланса). Miete — расход (аренда).
19. **Жёсткий и гибкий пункт Учёбы.** Жёсткий — есть официальный срок (HA, тесты, Hausarbeit, сдачи); гибкий — без него (лекции, сверки, подготовка). По умолчанию `is_fixed = due_date is not null`, на карточке можно переключить.
20. **Автоперенос гибких (Учёба).** При открытии приложения в новой неделе незакрытые гибкие пункты прошлых недель переезжают в текущую, `rollover_count += 1`. Проверка на клиенте, без серверного cron, идемпотентная: повторный запуск ничего не меняет. Пункты идут по порядку (неделя, `ready_by`, `sort_order`); каждый переносится, если с ним загрузка текущей недели не превышает максимум, иначе остаётся в своей неделе. Перенос вручную в «Ждут решения» тоже увеличивает `rollover_count`.
21. **«Ждут решения».** Незакрытые гибкие пункты прошлых недель, которые не влезли при автопереносе. Баннер на Учёбе и шаг воскресного обзора: выбрать неделю или снять. Молча не переносятся.
22. **«Застряло».** Пункт с `rollover_count ≥ 2`. Действия: разбить на части, снять, поставить на конкретную неделю.
23. **Жёсткие не двигаются.** Жёсткий пункт остаётся в своей неделе: после «готово к» — горит, после срока — «просрочено» с действиями «сдано позже» (готово) и «снять».
24. **Работа и Тело без автопереноса.** Пункт Работы висит до смены статуса; пропущенный день привычек просто прошёл; разовые задачи и визиты Тела — обычные пункты с видами сроков.
25. **Скор активности** = `minutes / 10 × points_per_10min` типа. Скор недели = сумма за пн–вс, сравнивается с целью этапа (`targets.activity_points_week`).
26. **Строки недель (18a).** «Вид» операции (`entry_kind`): «бюджет недели» / «итог недели». Бюджет недели — план трат, а не одно списание: вопроса «Списалось?» нет; когда неделя закончилась, строка уходит из плана (факт недели — траты из приложения); в текущей неделе прогноз вычитает большее из бюджета и уже потраченного по недельным категориям (траты через «+»; разовые строки плана — отдельно), будущие недели — целиком. «Неделя N (факт)» — итог недели из Excel: траты из приложения за эту неделю остаются в статистике категорий (правило 2), но в баланс не идут.
27. **Приём активен**, если `start_date ≤ сегодня` и (`end_date` пусто или `end_date ≥ сегодня`). «Закончила» ставит `end_date = сегодня`.
28. **Регулярные операции** (`rules/recurring.ts`). Правило даёт виртуальные плановые операции — повторения — от первой даты до горизонта; в базу они не пишутся и участвуют везде, где план (баланс, прогноз, «Месяцы», график, «Дальше по плану», операции месяца, вопросы правила 18, календарь, «Неделя вперёд»). Даты всегда от первой: 31-е в коротком месяце — последний день (31.01 → 28.02 → 31.03), 29.02 раз в год — 28.02. Ответ на повторение (подтвердить, другая дата, убрать из плана, правка) создаёт строку `transactions` с `recurring_id` + `occurrence_date`; она закрывает повторение в любом состоянии, «Вернуть» сразу после ответа удаляет её. Пауза скрывает все неотвеченные повторения, и прошлые. Уже заведённые похожие операции (тот же вид, похожее название, дата рядом: ±3 / ±10 / ±20 дней для недели / месяца / года) привязываются к повторениям только по «Привязать N».
29. **Правка регулярной** (`rules/recurringEdit.ts`). Без ответов правится на месте целиком. Сумма, название, счёт, группа, конверт, заметка, пауза — всегда на месте. Если ответы есть и меняется расписание (первая дата, частота, интервал): старое правило закрывается днём перед новой первой датой (более ранний конец сохраняется), создаётся новое. Новая первая дата — строго после последнего повторения с ответом; по умолчанию — следующая дата старого расписания после него; ближе одного интервала нового расписания — предупреждение без запрета («В декабре уже есть ответ 1.12. Точно ещё и 20.12?»).
30. **Счета и группы** (`rules/accounts.ts`, 18.11.2026). Группа «Баланс» — план и прогноз; «Подушка» — свой прогноз; «Отдельно» — только обзор. Старт по счетам — строки «старт» со счётом (конец дня 18.11): с него остаток счёта = старт + операции после старта, остаток группы — сумма её счетов; до старта — общий «котёл», как раньше. Строка без счёта — «Баланс». Траты — только со счетов «Баланса» (база и формы); доход — на любой счёт.
31. **Перевод** — всегда «откуда → куда», два разных счёта; не доход и не расход, в «Месяцы» не идёт. Внутри группы итог не меняет, между группами — уменьшает одну и увеличивает другую. Трата из конверта, чьи деньги не на «Балансе», — с переводом со счёта конверта на ту же сумму и дату («Сначала перевод с …»).
32. **Отложено и свободно.** На счёте отложено: конверт — «Осталось» (плановая трата из него не уменьшает, подтверждённая — уменьшает); цель — min(сейчас, цель); долг «я должна» — сколько осталось вернуть. Свободно = всего − отложено (может быть меньше нуля).
33. **«Деньги» со старта.** «Месяц» («сейчас», план, график, «Месяцы») и сверка считают «Баланс» со старта; график начинается со старта, если он позже 1-го числа; в «Месяцах» месяц старта помечен. Прогноз «Подушки» — её плановые и регулярные доходы и переводы через границу группы, без трат «Жизни».
34. **Прогноз «Баланса»** (`rules/forecast.ts`). От факта сейчас плюс неотвеченные плановые до горизонта: плановые и регулярные операции так, как они меняют «Баланс» (перевод в «Подушку» — минус, пара «Депозит → Основной + вернуть» — ноль), и «Жизнь» по сценарию: **по плану** — строка бюджета недели, иначе сумма лимитов, после последних лимитов — среднее последних 4 недель с лимитами больше нуля (неделя нулей — ноль); **по темпу** — медиана «Жизни» за 4 полные недели (итог недели или траты с недельной категорией без конвертов), меньше 3 недель с данными — «мало данных»; **осторожно** — большее из двух каждую неделю. Строки бюджета недели заменяются, не прибавляются; «Жизнь» — поровну по дням. Самая низкая точка — самый низкий день, при равенстве самый ранний. «Месяцы» с месяца сегодня: «На конец» — «по плану», в «Расходе» — «Жизнь» по плану вместо строк бюджета.
35. **«Свободно до {дата}»** — до ближайшего планового дохода в «Баланс» (нет — до горизонта), дни до него: факт сейчас − что уходит из «Баланса» по плану (с неотвеченными) + плановые переводы в «Баланс» − «Жизнь» по плану − отложенное на счетах «Баланса» (конверты — «Осталось», долги «я должна»; их плановые траты внутри резерва, резерв = большее из остатка и запланированного). Цели живут на «Подушке» и не вычитаются. Неотвеченный доход прошлой даты не прибавляется. Меньше нуля — как есть.
36. **Прогноз цели.** Сейчас — остаток счёта (цель одна на нём) или последняя доля; «нужно ≈ X € в месяц до срока · ещё Y €» (меньше месяца до срока — только «ещё Y €»); темп — по счёту со старта или по двум долям, не меньше 14 дней истории, иначе «темпа пока нет»; не растёт — «остаток не растёт».
37. **Темп недели** — «при таком темпе к воскресенью ≈ X € из лимита Y €»: потрачено / прошедшие дни × 7, со среды по субботу, только текущая неделя; выше лимита — янтарь.

## 5. Экраны

Нижний таб-бар: **Сегодня · Деньги · Работа · Учёба · Тело**. Кнопка «+» на всех экранах, кроме обзора; что она добавляет — решает экран (см. «Спокойная структура», 16.11.2026). Внутри сферы — главный вид и список «Ещё» (вкладок нет).

Сон — утренняя отметка: счётчик «− 7,5 ч +» в карточке привычек, первый тап ставит прошлое значение. По времени суток: до 18:00 «Вечер» — одна строка внизу (открывается тапом), с 18:00 — полный блок сразу под вопросами, в заголовке итог дня «сделано N · потрачено X €». Два и больше вопросов — одно место «Ждут ответа · N», по одному, со стрелками. Графиков на «Сегодня» нет.
- **Карточка пункта** (все сферы): название, статус, виды сроков (день и время / с даты / дедлайн и время), метки «горит», «срок прошёл», «перенесено ×N», «застряло»; у Учёбы — переключатель «жёсткий пункт»; лист действий для вопросов (три действия).

Сверка в «Месяце»: остатки счетов из «Остатков» против расчёта на ту же дату.
- **Деньги:** Неделя (лимиты, траты, статус) · Операции (план/факт, «Пришло? / Списалось?», подтверждение одним тапом, фильтры) · Конверты · Месяцы (таблица как лист «Обзор») · Хотелки · закреплённые Правила · Графики · Календарь.
- **Работа:** Доска по статусам (на телефоне — сгруппированный список) · Список по Bereich · Bei wem nachhaken · Erfolge (записанный успех — пункт типа «Erfolg», или Erledigt с заполненным «что это дало»; пустое состояние — «…когда наберётся месяц записей») · Люди · Графики · Календарь. Пятничный быстрый обзор: открытые карточки по одной, «актуально» / «обновить».
- **Учёба:** Неделя (ёмкость, пункты по предметам, чекбоксы, баннер «Ждут решения», метки «перенесено ×N» / «застряло») · Дедлайны и тесты (обратный отсчёт, значок data_status) · Предмет (часы за семестр, все ↔ и ⚠) · Графики · Календарь.
- **Тело:** Отметка дня (привычки этапа или набор минимума, уход — список этапа, блок «Движение» — несколько активностей за день, лист «+ активность»: тип → минуты → заметка, скор дня) · Графики · Силовые (журнал + рост повторов по упражнению) · Замеры · Приём («Сейчас принимаю» и свёрнутый архив, кнопка «Закончила») · Задачи и визиты · Справка · Календарь.
- **Воскресный обзор:** мастер из 5 шагов (Деньги → Тело → Учёба → Работа → Неделя вперёд), любой шаг можно пропустить. В шаге Учёбы — «Ждут решения» и «Застряло».
- **Настройки:** тема, Активности (типы, интенсивность, очки за 10 минут, скрыть/показать, порядок), Этапы (набор минимума, уход, цели недели), экспорт JSON/CSV, импорт JSON (восстановление), выход.
- **Вход:** e-mail + пароль → «Войти» (поля с `autocomplete="username"` / `"current-password"` для менеджера паролей). Ниже — запасная кнопка «Войти по ссылке из письма» для браузера.

Жесты: свайп вправо — готово, влево — перенести; долгий тап — карточка. Всё сохраняется само. Состояния: пусто, всё выполнено, просрочено, перерасход, офлайн (очередь), загрузка (скелетоны). Тап-зоны ≥ 44 px, контраст AA, светлая и тёмная тема.

### Календарь

Только внутри приложения, без экспорта .ics и без синхронизации с внешними календарями.

- **Вход:** иконка календаря в шапке «Сегодня» рядом с настройками; в каждой сфере — вид «Календарь», отфильтрованный по этой сфере. Шестой вкладки нет.
- **Виды:** Месяц (точки цвета сферы под датой, тап по дню — лист дня со списком) и Неделя (дни столбиком, события со временем).

- **Фильтры** чипами по сферам, состояние запоминается (localStorage).
- Тап по событию открывает карточку пункта; «+» в календаре создаёт пункт на выбранный день.

## 6. Импорт из Excel

Файлы лежат в `data/`. Скрипт идемпотентный (повторный запуск обновляет, а не дублирует — по `source_id`), есть режим `--dry-run` со сводкой. Даты Excel хранятся числом (46308 = 13.10.2026) — перевести в даты. Даты-тексты вида «Fr 23.10», «Mi 28.10 10:00», «Fr 30.10 (допущ.)» — разобрать; год: окт–дек → 2026, янв–апр → 2027.

**Dry-run не запускать, пока я не напишу, что данные в `data/` отредактированы.** Перед dry-run заново проверить структуру листов и сообщить, если колонки изменились.

**Budget_Oct-Dec_2026.xlsx** — строго по `docs/EXCEL_FORMAT.md` (листы «Статьи», «Недели», «Конверты», «Долги», «Остатки», «Правила», «Календарь» — архивом). Нет обязательной колонки или значение не из списка — импорт останавливается с листом, строкой и колонкой; ничего не угадывается по названиям. Пункты ниже — старый формат (до 12.11.2026), оставлены как история.

## Без Excel (12.11.2026)

Источник всех данных — приложение и его база. Файлы в `data/` — архив переноса; запись из них выключена (`import.py` пишет только с `--excel-is-source`), `import:check` остаётся для сверки.

- **Операция** (Деньги → Месяц → «+ Операция», тап по строке — правка): вид (расход · доход · перевод), название, сумма, дата, статус (план · факт), группа, категория недели (только расход группы «Жизнь» — идёт в лимит), счёт, конверт (только расход, только тип «конверт»), долг, заметка. Строка недели («Неделя N») меняет только сумму, дату и заметку. «Убрать из плана» — `cancelled_at` (строка остаётся, можно вернуть); операцию, созданную в приложении, можно удалить.

- Проверка §6 «баланс = Excel» снята. `test:import` сверяет контрольные числа Excel (задачи Работы, пункты «Чеклиста», часы Н04) с архивом — бэкапом 12.11.2026 сразу после импорта (`data/archive/excel-final-2026-11-12.json`, не в git; путь меняется через `LIFEHUB_ARCHIVE_BACKUP`; нет файла — эти проверки пропускаются с причиной), а не с живой базой: в приложении пункты правятся, переносятся и снимаются. Живую базу проверяет только по форме (одна строка старта, конечный план до горизонта).

## Табличный вид (ноутбук, 12.11.2026)

От 1024 px: нижняя панель — боковая; в Работе и Учёбе переключатель «Список / Таблица» (выбор хранится на устройстве; на узком экране — всегда список).

- **Учёба:** неделя, предмет, тип, что закрыть, часы, срок, «готово к», гибкий / жёсткий (в базу — только выбор, отличный от правила 19), ✓. Фильтры: «С этой недели», «Закрытые», чипы предметов, поиск. Группировка: по неделе, по предмету.
- **Таблица:** сортировка кликом по заголовку (по возрастанию → по убыванию → без), пустые всегда внизу. Видимость и ширина колонок хранятся на устройстве. Правка в ячейке: клик или Enter — правка, Enter — сохранить, Esc — отмена, Tab — сохранить и дальше; стрелки, Tab, Home/End — по ячейкам; ✓ — пробел. Неверное значение (часы словом, пустой Titel) не сохраняется, поле подсвечено.

## Заметка дня и журнал (12.11.2026)

## Спокойная структура (16.11.2026)

Интерфейс стал перегруженным. Принцип: главное — сразу, остальное — на один тап глубже; функции не убираются.

- **«Сегодня»** — только день: обзор (когда пора), вопросы, «Вечер», привычки и сон, «Горит». Карточек сфер и строки недели нет — в сферы через таб-бар; номера недель — на экранах сфер, место недели — над датой.
- **Экран сферы** = главный вид + список «Ещё» внизу (строки со стрелкой). Каждый раздел — свой адрес с «‹» назад к сфере:
  - Деньги: неделя (вопросы, итог, категории, траты) · Ещё: Месяц (`/money/month`), Регулярные (`/money/recurring`), Конверты и долги (`/money/envelopes`), Хотелки (`/money/wishes`), Заметки (`/money/notes`).
  - Работа: доска (вопросы, Bereich, группы, пятничный обзор; на ноутбуке — «Список / Таблица») · Ещё: Люди, Архив и Erfolge, Заметки.
  - Учёба: неделя (вопросы, «Ждут решения», предметы, «Скоро»; «Список / Таблица») · Ещё: Предметы, Тесты и дедлайны, Заметки.
  - Тело: день (минимум, привычки, движение, уход, «Вечер», заметка дня) · Ещё: Задачи и визиты, Графики (с долей привычек недели), Сила, Замеры, Приём, Этап, Справка и заметки.
- **«+» добавляет то, на что смотришь.** На «Сегодня» (и в календаре, на выбранный день) — список «Добавить»: Трата · Дело · Задача по работе · Учёба · Тело · Заметка (в календаре — без траты и заметки); каждая строка открывает форму своей сферы, «‹» возвращает к списку. В сферах — сразу своя форма:
  - Деньги → неделя: трата (клавиатура, тап по категории = сохранение); Месяц — операция; Регулярные — регулярный платёж; Конверты и долги — выбор «Конверт или цель / Долг»; Хотелки — хотелка (лист); Заметки — заметка сферы.
  - Работа → доска: задача — Titel, Bereich, Prio, Fällig («Без срока» по умолчанию); под «Ещё поля» — Typ (Aufgabe по умолчанию), Nächster Schritt, Wartet auf. Люди — человек (лист); Архив — Erfolg.
  - Учёба: пункт — что закрыть, предмет (чипы из уже заведённых), часы (счётчик по 0,5, 0 — без оценки), неделя (эта / следующая — `week_id`); под «Тип и срок» — тип и срок (срок даёт «готово к» по правилу 6, гибкий/жёсткий — по правилу 19).
  - Тело → день: активность на показанный день (и в «минимуме»); Задачи и визиты, Этап — «Сделать до» (срок) или «Визит в день» (`happens_on` + время, потом «Состоялось?»); Графики — активность; Сила, Замеры, Приём — свои листы.
- Кнопок «+ …» внутри экранов нет (кроме призыва в пустом состоянии) — добавляет только «+». Поясняющие строки, которые повторяются каждый день, убраны.

В листе правила — «Пауза» / «Снять с паузы»; «Удалить» — пока ни одно повторение не отвечено, потом правило заканчивается последней датой.

- **«Сделать регулярным»** в листе плановой операции (не отвеченной, не убранной, не из правила, не строки недели): лист правила, заполненный из операции (первая дата — её дата); после сохранения операция — первое повторение, остальные похожие — через «Уже есть в плане».
- **Повторение в листе операции:** «Сохранить» и «Убрать из плана» создают строку повторения; удалять нечего — правило меняется в «Регулярных». В «Дальше по плану» — метка «регулярный» и ссылка «Регулярные · N».
- **Запись:** правило и привязки идут через офлайн-очередь одной цепочкой (сначала правила, потом операции); id создаются на клиенте. Бэкап — формат v2 (с `recurring`), v1 читается.
