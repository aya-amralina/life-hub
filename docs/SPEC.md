# Life Hub — спецификация для разработки

Личное веб-приложение (PWA), которое заменяет четыре Excel-трекера: бюджет, задачи Localiser, учебный план WiSe 26/27 и глоу-ап. Пользователь один. Главный экран «Сегодня» собирает главное из всех сфер, раз в неделю — «Воскресный обзор».

Цели: отметка дня ≤ 10 секунд, любая отметка ≤ 3 тапа, итоги недели за 5–10 минут, 0 € в месяц.

Визуал — из дизайна Claude Design (handoff-бандл или папка `design/`). Логика и данные — из этого документа. При расхождении: внешний вид — по дизайну, поведение — по SPEC.

## 2. Деплой и окружения (бесплатно)

1. **GitHub** — приватный репозиторий `life-hub`, ветка `main` = прод.
2. **Supabase Free** — один проект, регион Frankfurt (eu-central-1).
   - Схема — только миграциями: `supabase/migrations/*.sql`, применяются `npx supabase db push`.
   - Auth: e-mail magic link. Site URL = прод-адрес на Vercel. Redirect URLs: прод-адрес, `http://localhost:5173`.
   - После создания моего пользователя — выключить регистрацию новых пользователей.
   - Бесплатный проект ставится на паузу после 7 дней без активности. При ежедневном использовании это не грозит. Опционально (этап 4): GitHub Action раз в сутки делает лёгкий запрос к базе.
3. **Vercel Hobby** — импорт репозитория, пресет Vite.
   - Env: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` (Production и Preview).
   - `vercel.json` с rewrite всех путей на `/index.html` (SPA).
   - Preview-деплой на каждую ветку.
4. **Локально** — `.env.local` с теми же переменными плюс `SUPABASE_SECRET_KEY` только для скрипта импорта и локальных тестов.

**Ключи API — только нового формата** (legacy `anon` / `service_role` JWT Supabase выводит из употребления к концу 2026): `sb_publishable_…` во фронтенде, `sb_secret_…` локально. Это не JWT: они передаются только в заголовке `apikey`, никогда как `Authorization: Bearer`. Publishable работает от роли Postgres `anon`, secret — от `service_role` (обходит RLS).

### Безопасность и приватность

- RLS на каждой таблице: колонка `user_id uuid not null default auth.uid()`, политики `using (user_id = auth.uid()) with check (user_id = auth.uid())` для select/insert/update/delete.
- Права явно в миграциях (в проекте выключено «Automatically expose new tables», включено «Enable automatic RLS»): `grant select, insert, update, delete` для `authenticated` и `service_role` (импорт); у `anon` прав нет.
- Secret key (`sb_secret_…`, роль `service_role`) никогда не попадает во фронтенд, в переменные с префиксом `VITE_`, в git и в логи. Сборка падает, если в `VITE_*` оказался секретный ключ.
- `.gitignore`: `.env*`, `data/`, `*.xlsx`, экспортированные дампы.
- Фото не хранятся (только отметки «фото сделано»).
- Скрипт импорта не печатает содержимое строк — только счётчики и ошибки с номером строки.

## 4. Бизнес-правила (считаются, не хранятся; каждое покрыто unit-тестом)

1. **Баланс и прогноз.** Остаток после каждой операции = накопленная сумма со знаком (opening и income +, expense −, transfer 0) в порядке даты. «На счетах 31.12» = остаток на 31.12 с учётом плановых операций.
2. **Неделя денег.** Факт = сумма expense с недельной категорией и без `envelope_id` за неделю. Отклонение = факт − лимит. Статус: ≤ 0 «в лимите», > 0 «перерасход».
3. **Перерасход режется следующей неделей.** При перерасходе приложение предлагает уменьшить лимит следующей недели на сумму перерасхода (только после подтверждения).
4. **Конверты** не входят в лимит недели; карточка конверта показывает заложено / потрачено / осталось.
5. **Хотелки 48 часов.** Если `now − added_at ≥ 48 ч` и решения нет — показать вопрос «всё ещё нужно?».
6. **Готово к** (Учёба) = срок − 2 дня; если выпало на Пн или Вс — сдвиг на предыдущую Сб. Пример: срок Ср 28.10 10:00 → готово к Сб 24.10.
7. **Загрузка недели** = Σ `hours_est` пунктов учёбы недели. Статус: ≤ база «ок», ≤ максимум «нужен Do/Sa ½», > максимум «перегруз». База по умолчанию 27 ч, максимум 36 ч; неделя с режимом ½ — 13,5 / 18.
8. **Перенос.** «Перенести на следующую неделю» меняет `week_id` и сразу пересчитывает загрузку обеих недель.
9. **Status alt.** Пункт Работы не в Erledigt/Verworfen и `updated_at` старше 14 дней.
10. **Nachhaken.** Счётчик по людям: статус Wartet auf Antwort или Blockiert и имя человека встречается в `waiting_on`.
11. **Горит.** Невыполненные пункты всех сфер, где `coalesce(ready_by, due_date) ≤ сегодня + 3 дня`, плюс просроченные. Сортировка по дате.
12. **Этап глоу-апа** определяется по дате (`plan_stages`) и задаёт набор привычек и цели недели. Не начавшиеся привычки скрыты.
13. **Режим «минимум»** засчитывает день как выполненный.
14. **Процент привычек недели** = отмеченные привычки / (активные привычки × прошедшие дни недели). Стриков с обнулением нет.

## 5. Экраны

Нижний таб-бар: **Сегодня · Деньги · Работа · Учёба · Тело**. Кнопка «+» (bottom sheet: трата / пункт / заметка) на всех экранах. Внутри сферы — сегментированные табы.

- **Сегодня:** строка недели («Неделя 5 бюджета · Н04 учёба · неделя 1 глоу-апа · у сестры»), привычки дня, «Горит», полоса лимита недели + «+ трата», Работа (In Arbeit + nachhaken), Учёба (часы недели + ближайший тест с обратным отсчётом), вечерний блок (энергия, сон, настроение, провал — ряды кнопок).
- **Деньги:** Неделя (лимиты, траты, статус) · Операции (план/факт, подтверждение одним тапом, фильтры) · Конверты · Месяцы (таблица как лист «Обзор») · Хотелки · закреплённые Правила.
- **Работа:** Доска по статусам (на телефоне — сгруппированный список) · Список по Bereich · Bei wem nachhaken · Erfolge (Erledigt + поле «что это дало») · Люди. Пятничный быстрый обзор: открытые карточки по одной, «актуально» / «обновить».
- **Учёба:** Неделя (ёмкость, пункты по предметам, чекбоксы) · Дедлайны и тесты (обратный отсчёт, значок data_status) · Предмет (часы за семестр, все ↔ и ⚠).
- **Тело:** Отметка дня · Итоги недели (графики) · Силовые (журнал + график повторов по упражнению) · Замеры · Задачи и визиты · Справка.
- **Воскресный обзор:** мастер из 5 шагов (Деньги → Тело → Учёба → Работа → Неделя вперёд), любой шаг можно пропустить.
- **Настройки:** тема, экспорт JSON/CSV, импорт JSON (восстановление), выход.
- **Вход:** поле e-mail → «Отправить ссылку».

Жесты: свайп вправо — готово, влево — перенести; долгий тап — карточка. Всё сохраняется само. Состояния: пусто, всё выполнено, просрочено, перерасход, офлайн (очередь), загрузка (скелетоны). Тап-зоны ≥ 44 px, контраст AA, светлая и тёмная тема.

## 6. Импорт из Excel

Файлы лежат в `data/`. Скрипт идемпотентный (повторный запуск обновляет, а не дублирует — по `source_id`), есть режим `--dry-run` со сводкой. Даты Excel хранятся числом (46308 = 13.10.2026) — перевести в даты. Даты-тексты вида «Fr 23.10», «Mi 28.10 10:00», «Fr 30.10 (допущ.)» — разобрать; год: окт–дек → 2026, янв–апр → 2027.

**Budget_Oct-Dec_2026.xlsx**
- «Статьи» → `transactions`: ID → `source_id`; S0 → `opening`; Знак +1 → income, −1 → expense; Группа → `grp`; Статья → `title`; Заметка → `note`. Дата ≤ дня импорта → подтверждено, позже → план. Недельные траты «Неделя N (факт)» — expense группы «Жизнь».
- «Недели» → `weeks` (даты, «Где» → `place_mode`, номер недели) и `week_limits` (6 категорий). Все недели в `weeks` строго пн–вс, без исключений: неделя 1 бюджета = 12.10–18.10, а старт бюджета 13.10 задаёт операция S0.
- «Календарь» → не отдельная сущность. «Счёт» → `account` у сопоставленной операции из «Статей»; «Что сделать» → `note` этой операции (дописывается к заметке). Задачи из него не создаются; `--dry-run` показывает отдельным списком строки, похожие на открытые действия, — какие станут задачами Денег, решаю я.
- «Конверты и копилки» → `envelopes`. «Правила» → `notes` (sphere money, pinned). «Обзор» и «Отчёт недели» не импортируются — считаются.

**Localiser_Aufgaben-Tracker.xlsx**
- «Dev Aufgaben» → `items` (sphere work). Колонки: Titel, Typ, Bereich, Status, Prio, Fällig am, Hinweis (не импортировать — считается), Nächster Schritt, Wartet auf / blockiert durch, Beteiligte (→ `people[]`), ClickUp-Ticket, Branch / PR / Links, Details & Notizen, Angelegt, Aktualisiert. Пустые строки пропустить.
- Единственный источник задач Работы — «Dev Aufgaben». У строки с пустым Titel (Branch `fix/h2_secret_logging`) название задаётся явно: «PR 1: Secret-Logging fixen».
- «Organisatirisch» неактуален: не импортируется и ни с чем не сравнивается.
- «Legende» → `people` (имя + роль) и `notes` (sphere work).

**Wochenplan_WiSe2627_alternativ.xlsx**
- «Чеклист» → `items` (sphere study): Неделя → `week_id`, Предмет → `area`, Тип, Что закрыть → `title`, «Связь ↔ / ловушка ⚠» → разделить по « · » на `synergy` и `trap`, ~ч → `hours_est`, Срок → `due_date`/`due_time`, Готово к → `ready_by`, ✓ → `done_at`.
- «Дедлайны и тесты» → сопоставить с пунктами чеклиста (предмет + дата); совпавшим проставить `data_status`, остальные создать как пункты типа Тест/Орга. «подтверждено…» → confirmed, «допущение…» → assumption, «проверить» → check.
- «План по неделям» → `weeks` (режим, ёмкость база/макс). «Допущения и открытые вопросы» → `notes`.

**Глоу_ап___трекер.xlsx**
- «Трекер» → `daily_logs` (только строки с данными; строку «пример» пропустить).
- «Сила» → `strength_sets`, «Замеры» → `measurements` (пустые даты замеров — как напоминания-пункты сферы body).
- «Задачи» и «Врачи» → `items` (sphere body; визиты — тип «Визит»).
- «Обзор» (этапы и привычки) и «Недели» (цели) → `plan_stages` и события в `weeks`.
- «Программа», «Питание», «Уход», правила гибкости из «Обзора» → `notes` (sphere body).
- «Бюджет» не импортировать — дубль сферы Деньги.

**Проверки после импорта (автотест):**
- остаток на 31.12.2026 = **1788,14 €**, разница с «Обзор» = 0;
- число задач Работы = число непустых строк «Dev Aufgaben»;
- сумма часов учёбы за неделю Н04 = **27,5 ч**;
- число пунктов чеклиста = число строк «Чеклист».

## 7. Этапы и критерии готовности

1. **Каркас.** Проект, CLAUDE.md, Supabase (миграции `weeks`, `items`, RLS), вход по magic link, таб-бар, пустой «Сегодня», PWA (manifest, иконки, установка), деплой на Vercel. *Готово:* прод-ссылка открывается, приложение ставится на телефон, вход работает, данные синхронизируются между телефоном и ноутбуком.
2. **Ежедневные отметки.** Тело: отметка дня и этапы. Деньги: быстрая трата и лимит недели. Учёба: экран недели. Работа: список со статусами. «Сегодня» собирает это вместе. *Готово:* день отмечается без Excel.
3. **Импорт и логика.** Все таблицы схемы, скрипт импорта, правила раздела 4, доска Работы, nachhaken, Status alt, дедлайны, перенос, силовые, замеры, конверты, прогноз. *Готово:* проверки раздела 6 зелёные.
4. **Обзор, графики, экспорт.** Воскресный обзор, итоги недель и графики, экспорт/импорт JSON и CSV, хотелки 48 ч, офлайн-очередь, опциональный keep-alive. *Готово:* воскресенье проходит целиком в приложении.
5. **Потом.** Push-уведомления, табличный вид для ноутбука, разбор недели через Claude API, разбор body comp PDF в сфере Тело.
