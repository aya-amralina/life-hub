# Life Hub — спецификация для разработки

Личное веб-приложение (PWA), которое заменяет четыре Excel-трекера: бюджет, задачи Localiser, учебный план WiSe 26/27 и глоу-ап. Пользователь один. Главный экран «Сегодня» собирает главное из всех сфер, раз в неделю — «Воскресный обзор».

Цели: отметка дня ≤ 10 секунд, любая отметка ≤ 3 тапа, итоги недели за 5–10 минут, 0 € в месяц.

Визуал — дизайн-система и экраны Claude Design в `design/`; рабочая выжимка — `docs/DESIGN.md`. Экраны, которых нет в дизайне, собираются из той же системы в стиле экранов 3a–3o (светлая и тёмная тема, пустые состояния, тот же тон текстов). Логика и данные — из этого документа. При расхождении: внешний вид — по дизайну, поведение — по SPEC.

## 2. Деплой и окружения (бесплатно)

1. **GitHub** — приватный репозиторий `life-hub`, ветка `main` = прод.
2. **Supabase Free** — один проект, регион Frankfurt (eu-central-1).
   - Схема — только миграциями: `supabase/migrations/*.sql`, применяются `npx supabase db push`.
   - Auth: e-mail + пароль (основной способ, `signInWithPassword`); magic link — запасной вариант для браузера. Своего SMTP нет, шаблоны писем стандартные. Site URL = прод-адрес на Vercel. Redirect URLs: прод-адрес, `http://localhost:5173` (нужны для magic link).
   - Мой пользователь и отдельный тестовый пользователь создаются вручную с паролем (Dashboard → Authentication → Users), после этого регистрация новых пользователей выключена. Автотесты входят только под тестовым пользователем (`LIFEHUB_TEST_EMAIL`, `LIFEHUB_TEST_PASSWORD`) и не трогают мои данные; `LIFEHUB_EMAIL` — моя почта для импорта.
   - Бесплатный проект ставится на паузу после 7 дней без активности. При ежедневном использовании это не грозит. Опционально (этап 5): GitHub Action раз в сутки делает лёгкий запрос к базе.
3. **Vercel Hobby** — импорт репозитория, пресет Vite.
   - Env: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` (Production и Preview).
   - `vercel.json` с rewrite всех путей на `/index.html` (SPA).
   - Preview-деплой на каждую ветку.
4. **Локально** — `.env.local` с теми же переменными плюс `SUPABASE_SECRET_KEY` только для скрипта импорта и локальных тестов.

**Ключи API — только нового формата** (legacy `anon` / `service_role` JWT Supabase выводит из употребления к концу 2026): `sb_publishable_…` во фронтенде, `sb_secret_…` локально. Это не JWT: они передаются только в заголовке `apikey`, никогда как `Authorization: Bearer`. Publishable работает от роли Postgres `anon`, secret — от `service_role` (обходит RLS).

### Безопасность и приватность

- RLS на каждой таблице: колонка `user_id uuid not null default auth.uid()`, политики `using (user_id = auth.uid()) with check (user_id = auth.uid())` для select/insert/update/delete.
- Права явно в миграциях (в проекте выключено «Automatically expose new tables», включено «Enable automatic RLS»): `grant select, insert, update, delete` для `authenticated` и `service_role` (импорт); у `anon` прав нет.
- Secret key (`sb_secret_…`, роль `service_role`) никогда не попадает во фронтенд, в переменные с префиксом `VITE_`, в git и в логи. Сборка падает, если в `VITE_*` оказался секретный ключ.
- `.gitignore`: `.env*`, `data/`, `*.xlsx`, экспортированные дампы.
- Фото не хранятся (только отметки «фото сделано»).
- Скрипт импорта не печатает содержимое строк — только счётчики и ошибки с номером строки.

### Сроки у пунктов: четыре вида (все сферы)

У пункта может быть ноль, одна или несколько дат. Вид определяется по заполненным полям, отдельного поля «вид» нет.

| Вид | Поля | Поведение |
| --- | --- | --- |
| **Открытый** | дат нет | висит до смены статуса |
| **В определённый день** | `happens_on`, `happens_time` (необяз.) | в этот день появляется в «Сегодня» и в календаре; если день прошёл, а пункт не закрыт — вопрос «Состоялось?»: «да» → готово, «другая дата», «отменить» |
| **Начинается с даты** | `starts_on` | до этой даты скрыт из активных списков, виден в свёрнутой группе «Скоро» и в календаре (отметка «начало»); с этой даты — обычный пункт |
| **С дедлайном** | `due_date`, `due_time` (необяз.) | «Горит» за 3 дня (у Учёбы — от «готово к»), после срока — «просрочено» |

`starts_on` и `due_date` можно сочетать («начать с 01.12, сдать до 15.12»); старт не позже срока (проверка в базе). Статусы Работы остаются как в таблице.

### Справочники (константы в коде)

- **Статусы Работы:** Offen, In Arbeit, Im Review, Wartet auf Antwort, Blockiert, Geparkt, Erledigt, Verworfen. «Активные» = Offen, In Arbeit, Im Review. «Стоит» = Wartet auf Antwort, Blockiert, Geparkt.
- **Типы Работы:** Aufgabe, Bug, Anfrage, Offene Frage, Follow-up, Idee. **Prio:** Hoch, Mittel, Niedrig.
- **Bereich:** H2-Registrierung, H2-Marktplatz, Kundendashboard, Website & Marketing, Karriere & Rolle, Bachelorarbeit, Organisatorisches, LIS Front (+ добавление из выпадающего списка).
- **Учёба, типы:** Лекция, HA, Сверка, Задача, Тест, Подготовка, Орга, Hausarbeit, Туториум. Статус: открыто / готово / снято.

## 4. Бизнес-правила (считаются, не хранятся; каждое покрыто unit-тестом)

1. **Баланс и прогноз.** Остаток после каждой операции = накопленная сумма со знаком (opening и income +, expense −, transfer 0) в порядке даты. «На счетах 31.12» = остаток на 31.12 с учётом плановых операций.
2. **Неделя денег.** Факт = сумма expense с недельной категорией и без `envelope_id` за неделю. Отклонение = факт − лимит. Статус: ≤ 0 «в лимите», > 0 «перерасход».
3. **Перерасход режется следующей неделей.** При перерасходе приложение предлагает уменьшить лимит следующей недели на сумму перерасхода (только после подтверждения).
4. **Конверты** не входят в лимит недели; карточка конверта показывает заложено / потрачено / осталось.
5. **Хотелки 48 часов.** Если `now − added_at ≥ 48 ч` и решения нет — показать вопрос «всё ещё нужно?».
6. **Готово к** (Учёба) = срок − 2 дня; если выпало на Пн или Вс — сдвиг на предыдущую Сб. Пример: срок Ср 28.10 10:00 → готово к Сб 24.10.
7. **Загрузка недели** = Σ `hours_est` пунктов учёбы недели. Пороги — из ёмкости недели в `weeks`: ≤ `capacity_base_h` «ок», ≤ `capacity_max_h` «нужен Do/Sa ½», больше — «перегруз». По умолчанию 27 / 36 ч; неделя с режимом ½ — 13,5 / 18. Те же пороги у тепловой карты Учёбы.
8. **Перенос вручную.** «Перенести на следующую неделю» меняет `week_id` и сразу пересчитывает загрузку обеих недель.
9. **Status alt.** Пункт Работы не в Erledigt/Verworfen и `updated_at` старше 14 дней.
10. **Nachhaken.** Счётчик по людям: статус Wartet auf Antwort или Blockiert и имя человека встречается в `waiting_on`.
11. **Горит.** Незакрытые пункты всех сфер, где `coalesce(ready_by, due_date) ≤ сегодня + 3 дня` («горит», янтарный), плюс просроченные (`due_date < сегодня`, красный с подписью «срок прошёл»). Сортировка по дате. Пункты с `starts_on` в будущем и приём (`intake`) сюда не попадают.
12. **Этап глоу-апа** определяется по дате (`plan_stages`) и задаёт набор привычек, набор минимума и цели недели. Не начавшиеся привычки скрыты.
13. **Режим «минимум».** При включённом минимуме видны только привычки набора `minimum_habits` этапа, остальные скрыты. День засчитывается полностью (как все активные привычки), если отмечен весь набор; иначе считаются только отмеченные привычки набора. Текст карточки называет привычки набора («Минимум: вода и 10 минут на улице»).
14. **Процент привычек недели** = отмеченные привычки / (активные привычки × прошедшие дни недели), дни минимума — по правилу 13. Стриков с обнулением нет.
15. **Вид срока** пункта — по набору полей (раздел 3): открытый / в определённый день / начинается с даты / с дедлайном; `starts_on` сочетается с дедлайном.
16. **«Скоро».** Пункт с `starts_on > сегодня` скрыт из активных списков и из «Горит», виден в свёрнутой группе «Скоро» своей сферы и в календаре.
17. **«Состоялось?».** Незакрытый пункт с `happens_on < сегодня` → вопрос на «Сегодня» и в своей сфере: «да» (готово), «другая дата» (новый `happens_on`), «отменить».
18. **«Пришло?» / «Списалось?».** Плановая операция (`is_planned`, без `confirmed_at`), у которой дата наступила (`date ≤ сегодня`), → вопрос на «Сегодня» и в Деньгах: для дохода — «Пришло?», для расхода и перевода — «Списалось?». Действия: «подтвердить» (сумму можно поправить), «другая дата», «отменить» (`cancelled_at`: строка остаётся, но выходит из плана и баланса). Miete — расход (аренда).
19. **Жёсткий и гибкий пункт Учёбы.** Жёсткий — есть официальный срок (HA, тесты, Hausarbeit, сдачи); гибкий — без него (лекции, сверки, подготовка). По умолчанию `is_fixed = due_date is not null`, на карточке можно переключить.
20. **Автоперенос гибких (Учёба).** При открытии приложения в новой неделе незакрытые гибкие пункты прошлых недель переезжают в текущую, `rollover_count += 1`. Проверка на клиенте, без серверного cron, идемпотентная: повторный запуск ничего не меняет. Пункты идут по порядку (неделя, `ready_by`, `sort_order`); каждый переносится, если с ним загрузка текущей недели не превышает максимум, иначе остаётся в своей неделе. Перенос вручную в «Ждут решения» тоже увеличивает `rollover_count`.
21. **«Ждут решения».** Незакрытые гибкие пункты прошлых недель, которые не влезли при автопереносе. Баннер на Учёбе и шаг воскресного обзора: выбрать неделю или снять. Молча не переносятся.
22. **«Застряло».** Пункт с `rollover_count ≥ 2`. Действия: разбить на части, снять, поставить на конкретную неделю.
23. **Жёсткие не двигаются.** Жёсткий пункт остаётся в своей неделе: после «готово к» — горит, после срока — «просрочено» с действиями «сдано позже» (готово) и «снять».
24. **Работа и Тело без автопереноса.** Пункт Работы висит до смены статуса; пропущенный день привычек просто прошёл; разовые задачи и визиты Тела — обычные пункты с видами сроков.
25. **Скор активности** = `minutes / 10 × points_per_10min` типа. Скор недели = сумма за пн–вс, сравнивается с целью этапа (`targets.activity_points_week`).
26. **Бюджет недели (18a).** Плановая строка «Неделя N: …» (`week_budget`) — план трат недели, а не одно списание: вопроса «Списалось?» нет; когда неделя закончилась, строка уходит из плана (факт недели — траты из приложения); в текущей неделе прогноз вычитает большее из бюджета недели и уже потраченного (траты группы «Жизнь»), будущие недели — целиком.
27. **Приём активен**, если `start_date ≤ сегодня` и (`end_date` пусто или `end_date ≥ сегодня`). «Закончила» ставит `end_date = сегодня`.

## 5. Экраны

Нижний таб-бар: **Сегодня · Деньги · Работа · Учёба · Тело**. Кнопка «+» (bottom sheet: трата / пункт / заметка) на всех экранах. Внутри сферы — сегментированные табы.

- **Сегодня:** шапка с иконками календаря и настроек; строка недели («Неделя 5 бюджета · Н04 учёба · неделя 1 глоу-апа · у сестры»), вопросы «Состоялось?» и «Пришло? / Списалось?», привычки дня (в режиме минимума — только набор), «Горит», полоса лимита недели + «+ трата», Работа (In Arbeit + nachhaken), Учёба (часы недели + ближайший тест с обратным отсчётом), вечерний блок (энергия, сон, настроение, провал — ряды кнопок). Графиков на «Сегодня» нет.
- **Карточка пункта** (все сферы): название, статус, виды сроков (день и время / с даты / дедлайн и время), метки «горит», «срок прошёл», «перенесено ×N», «застряло»; у Учёбы — переключатель «жёсткий пункт»; лист действий для вопросов (три действия).
- **Деньги:** Неделя (лимиты, траты, статус) · Операции (план/факт, «Пришло? / Списалось?», подтверждение одним тапом, фильтры) · Конверты · Месяцы (таблица как лист «Обзор») · Хотелки · закреплённые Правила · Графики · Календарь.
- **Работа:** Доска по статусам (на телефоне — сгруппированный список) · Список по Bereich · Bei wem nachhaken · Erfolge (записанный успех — пункт типа «Erfolg», или Erledigt с заполненным «что это дало»; пустое состояние — «…когда наберётся месяц записей») · Люди · Графики · Календарь. Пятничный быстрый обзор: открытые карточки по одной, «актуально» / «обновить».
- **Учёба:** Неделя (ёмкость, пункты по предметам, чекбоксы, баннер «Ждут решения», метки «перенесено ×N» / «застряло») · Дедлайны и тесты (обратный отсчёт, значок data_status) · Предмет (часы за семестр, все ↔ и ⚠) · Графики · Календарь.
- **Тело:** Отметка дня (привычки этапа или набор минимума, блок «Движение» — несколько активностей за день, лист «+ активность»: тип → минуты → заметка, скор дня) · Графики · Силовые (журнал + рост повторов по упражнению) · Замеры · Приём («Сейчас принимаю» и свёрнутый архив, кнопка «Закончила») · Задачи и визиты · Справка · Календарь.
- **Воскресный обзор:** мастер из 5 шагов (Деньги → Тело → Учёба → Работа → Неделя вперёд), любой шаг можно пропустить. В шаге Учёбы — «Ждут решения» и «Застряло».
- **Настройки:** тема, Активности (типы, интенсивность, очки за 10 минут, скрыть/показать, порядок), Этапы (набор минимума, цели недели), экспорт JSON/CSV, импорт JSON (восстановление), выход.
- **Вход:** e-mail + пароль → «Войти» (поля с `autocomplete="username"` / `"current-password"` для менеджера паролей). Ниже — запасная кнопка «Войти по ссылке из письма» для браузера.

Жесты: свайп вправо — готово, влево — перенести; долгий тап — карточка. Всё сохраняется само. Состояния: пусто, всё выполнено, просрочено, перерасход, офлайн (очередь), загрузка (скелетоны). Тап-зоны ≥ 44 px, контраст AA, светлая и тёмная тема.

### Графики (по сферам)

На «Сегодня» графиков нет. Все графики — Recharts, цвета сфер из дизайн-системы, светлая и тёмная тема, подписи осей на русском, пустое состояние с текстом.

| Сфера | Что показать |
| --- | --- |
| **Деньги** | линия баланса до 31.12: план против факта (подтверждённая операция сразу двигает линию факта); заполнение конвертов (заложено / потрачено / осталось) |
| **Работа** | доска по статусам; Erfolge по месяцам столбиками |
| **Учёба** | тепловая карта загрузки Н00–Н25 против ёмкости недели (ок / нужен Do/Sa ½ / перегруз — пороги по правилу 7); прогресс по предметам в часах |
| **Тело** | календарь привычек (как на GitHub); самочувствие с переключателем **День / Неделя / Месяц**; скор активностей по неделям против цели + таблица активностей; рост повторов по упражнению |

Самочувствие: настроение и энергия — линии по шкале 1–10, сон — столбики в часах на второй оси; день — значения по дням, неделя и месяц — средние. Пустые дни — разрывы линии, а не нули. Переключатель «Показать приём»: периоды из `intake` полосами на фоне графика, без выводов и подсказок о причинах — только наложение.

### Календарь

Только внутри приложения, без экспорта .ics и без синхронизации с внешними календарями.

- **Вход:** иконка календаря в шапке «Сегодня» рядом с настройками; в каждой сфере — вид «Календарь», отфильтрованный по этой сфере. Шестой вкладки нет.
- **Виды:** Месяц (точки цвета сферы под датой, тап по дню — лист дня со списком) и Неделя (дни столбиком, события со временем).
- **Что показывается:** пункты с `due_date`, `happens_on`, `starts_on` (отметка «начало»); тесты и дедлайны Учёбы; плановые операции Денег; дни замеров; недели с местом и режимом (поездки, Казахстан) — полосой поверх дней; границы этапов глоу-апа — полосой; периоды приёма — только если включён фильтр (по умолчанию выключен).
- **Фильтры** чипами по сферам, состояние запоминается (localStorage).
- Тап по событию открывает карточку пункта; «+» в календаре создаёт пункт на выбранный день.

## 6. Импорт из Excel

Файлы лежат в `data/`. Скрипт идемпотентный (повторный запуск обновляет, а не дублирует — по `source_id`), есть режим `--dry-run` со сводкой. Даты Excel хранятся числом (46308 = 13.10.2026) — перевести в даты. Даты-тексты вида «Fr 23.10», «Mi 28.10 10:00», «Fr 30.10 (допущ.)» — разобрать; год: окт–дек → 2026, янв–апр → 2027.

**Dry-run не запускать, пока я не напишу, что данные в `data/` отредактированы.** Перед dry-run заново проверить структуру листов и сообщить, если колонки изменились.

**Budget_Oct-Dec_2026.xlsx**
- «Статьи» → `transactions`: ID → `source_id`; S0 → `opening`; Знак +1 → income, −1 → expense; Группа → `grp`; Статья → `title`; Заметка → `note`. Дата ≤ дня импорта → подтверждено, позже → план. Недельные траты «Неделя N (факт)» — expense группы «Жизнь». Miete — расход.
- «Недели» → `weeks` (даты, «Где» → `place_mode`, номер недели) и `week_limits` (6 категорий). Все недели в `weeks` строго пн–вс, без исключений: неделя 1 бюджета = 12.10–18.10, а старт бюджета 13.10 задаёт операция S0.
- «Календарь» → «Счёт» в `account` сопоставленной операции из «Статей» (сумма и дата ±7 дней), «Что сделать» → её `note`; весь лист целиком — заметка «Календарь списаний (архив)» в Деньгах. Задачей Денег становится только действие на будущее: предложение из «Что сделать» с действием и сроком сегодня или позже (срок — дата в тексте, «до 13.11», иначе дата строки).
- Строки «Неделя N: …» без «(факт)» — бюджеты недель (`week_budget`, правило 26), плановые, без автоподтверждения. «Конверты и копилки» с типом «Долг» не импортируются.
- «Конверты и копилки» → `envelopes`. «Правила» → `notes` (sphere money, pinned). «Обзор» и «Отчёт недели» не импортируются — считаются.

**Localiser_Aufgaben-Tracker.xlsx**

Колонки: Titel (у первой колонки может не быть заголовка), Typ, Bereich, Status, Prio, Fällig am, Hinweis (не импортировать — считается), Nächster Schritt, Wartet auf / blockiert durch, Beteiligte (→ `people[]`), ClickUp-Ticket, Branch / PR / Links, Details & Notizen, Angelegt, Aktualisiert. Пустые строки пропустить.
- Единственный источник задач Работы — «Dev Aufgaben». У строки с пустым Titel (Branch `fix/h2_secret_logging`) название задаётся явно: «PR 1: Secret-Logging fixen».

- «Legende» → `people` (имя + роль) и `notes` (sphere work).

**Wochenplan_WiSe2627_alternativ.xlsx**

## 7. Этапы и критерии готовности

1. **Каркас.** Проект, CLAUDE.md, Supabase (миграции `weeks`, `items`, RLS), вход (e-mail + пароль, запасной — magic link), таб-бар, пустой «Сегодня», PWA (manifest, иконки, установка), деплой на Vercel. *Готово:* прод-ссылка открывается, приложение ставится на телефон, вход работает, данные синхронизируются между телефоном и ноутбуком.
2. **Ежедневные отметки.** Тело: отметка дня и этапы. Деньги: быстрая трата и лимит недели. Учёба: экран недели. Работа: список со статусами. «Сегодня» собирает это вместе. *Готово:* день отмечается без Excel.
3. **Логика и импорт.**
   - **3a. Логика без импорта.** Схема всех таблиц; виды сроков и карточка пункта, «Скоро», «Состоялось?»; перенос (автоперенос гибких, «Ждут решения», «застряло», жёсткие пункты); «Пришло? / Списалось?»; режим «минимум» по набору этапа; активности со скором (Отметка дня, Настройки → Активности, перенос `workout_*`); приём. Правила раздела 4 и экраны сфер, которым не нужны данные: доска Работы, nachhaken, Status alt, Erfolge, дедлайны, операции, конверты, прогноз, силовые, замеры. Экраны-списки, без графиков. *Готово:* всё это работает на данных, введённых вручную; правила раздела 4 покрыты тестами.
   - **3b. Импорт.** Скрипт импорта всех файлов (с новыми полями и активностями). Стартует только после моего сигнала, что данные в `data/` готовы. *Готово:* проверки раздела 6 зелёные.
4. **Визуализации и календарь.** Графики и календарь раздела 5. *Готово:* у каждой сферы, кроме «Сегодня», есть свой график; календарь показывает события всех сфер с фильтрами.
5. **Обзор и экспорт.** Воскресный обзор (с шагами «Ждут решения» и «Застряло»), экспорт/импорт JSON и CSV, хотелки 48 ч, офлайн-очередь, опциональный keep-alive. *Готово:* воскресенье проходит целиком в приложении.
6. **Потом.** Push-уведомления, табличный вид для ноутбука, разбор недели через Claude API, разбор body comp PDF в сфере Тело.
